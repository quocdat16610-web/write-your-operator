# Bài 0.1: Máy tính khởi động thế nào

## Mục tiêu

Hiểu chuyện gì xảy ra từ lúc bấm nút nguồn đến lúc kernel của bạn chạy dòng lệnh đầu tiên. Cuối bài, bạn tự viết một **boot sector 512 byte** mà BIOS nạp và chạy trực tiếp, không cần GRUB hay multiboot.

## Lý thuyết

### Ví dụ đời thường: chạy tiếp sức

Khởi động máy tính giống một cuộc **chạy tiếp sức**. Mỗi người chạy chỉ biết đủ để chạy đoạn của mình, rồi trao gậy cho người sau:

1. **CPU** vừa có điện thì chưa biết gì cả. Nó chỉ biết nhảy tới một địa chỉ cố định trong chip ROM trên bo mạch chủ.
2. **Firmware** (BIOS, hoặc UEFI trên máy mới) kiểm tra phần cứng (quá trình này gọi là POST), rồi đi tìm ổ đĩa khởi động được.
3. **Bootloader** (ví dụ GRUB) được firmware nạp vào. Nó biết đọc hệ thống file, tìm file kernel và nạp kernel vào RAM.
4. **Kernel**, tức chương trình của bạn, nhận gậy và từ đây toàn quyền điều khiển máy.

### So sánh với Python

Khi bạn gõ `python hello.py`, có rất nhiều thứ đã chuẩn bị sẵn cho bạn: hệ điều hành nạp trình thông dịch Python, cấp bộ nhớ, mở sẵn màn hình để `print()` dùng. Kernel thì **không có ai chuẩn bị gì cả**. Không có `print`, không có `malloc`, không có file. Chỉ có CPU, RAM, và vài dịch vụ tối thiểu firmware để lại. Viết OS nghĩa là tự làm phần "chuẩn bị sẵn" đó.

### Chuỗi khởi động của máy x86

```text
 Bấm nguồn
    │
    ▼
 CPU reset ──► nhảy tới 0xFFFFFFF0 (trong ROM BIOS)
    │
    ▼
 BIOS: POST (kiểm tra RAM, bàn phím, ổ đĩa...)
    │
    ▼
 BIOS đọc sector đầu tiên (512 byte) của ổ đĩa
    │   2 byte cuối có phải 55 AA không?
    │      ├── không → "not a bootable disk", thử ổ khác
    │      └── có    → chép 512 byte vào RAM tại 0x7C00, nhảy tới đó
    ▼
 Boot sector / bootloader (GRUB)
    │   chuyển CPU sang protected mode 32-bit, nạp kernel vào 1 MB
    ▼
 Kernel: _start trong boot.asm → kernel_main() trong kernel.cpp
```

### Real mode và protected mode

CPU x86 hiện đại vẫn **giả làm chip 8086 đời 1978** lúc vừa bật nguồn, để chạy được phần mềm cũ. Chế độ đó gọi là **real mode**:

| | Real mode (lúc bật máy) | Protected mode (kernel của bạn) |
|---|---|---|
| Độ rộng thanh ghi | 16 bit | 32 bit |
| Bộ nhớ dùng được | khoảng 1 MB | 4 GB |
| Bảo vệ bộ nhớ | không có | có (vòng ring 0 đến ring 3) |
| Gọi BIOS bằng `int` | được | không được |

Boot sector hôm nay chạy trong real mode, nên dùng được dịch vụ in chữ của BIOS. Kernel multiboot bạn đã viết thì GRUB (hoặc QEMU) đã chuyển sẵn sang protected mode, nên bạn phải tự ghi chữ vào bộ nhớ VGA ở `0xB8000`.

### Bản đồ 1 MB đầu tiên của RAM

```text
 0x00000000 ┌──────────────────────────────┐
            │ Bảng vector ngắt (IVT) 1 KB  │  BIOS dùng
 0x00000400 ├──────────────────────────────┤
            │ Vùng dữ liệu BIOS (BDA)      │
 0x00000500 ├──────────────────────────────┤
            │ Trống, dùng được             │  ◄── stack của boot sector mọc xuống từ 0x7C00
 0x00007C00 ├──────────────────────────────┤
            │ BOOT SECTOR (512 byte)       │  ◄── BIOS chép code của bạn vào đây
 0x00007E00 ├──────────────────────────────┤
            │ Trống, dùng được             │
 0x0009FC00 ├──────────────────────────────┤
            │ Vùng dữ liệu mở rộng (EBDA)  │
 0x000A0000 ├──────────────────────────────┤
            │ Bộ nhớ video (VGA)           │  0xB8000 = chữ trên màn hình
 0x000C0000 ├──────────────────────────────┤
            │ ROM của card màn hình, BIOS  │
 0x00100000 └──────────────────────────────┘  1 MB ◄── kernel multiboot nạp vào từ đây
```

Đây là lý do `linker.ld` của bạn đặt kernel ở **1 MB**: phía dưới đã bị BIOS, VGA và ROM chiếm gần hết.

### Multiboot: kernel của bạn khởi động thế nào

Kernel bạn đã có **không** phải boot sector. Khi chạy `qemu-system-i386 -kernel kernel.bin`, QEMU đóng vai một bootloader tuân theo chuẩn **Multiboot**:

1. Nó tìm trong 8 KB đầu của `kernel.bin` con số `0x1BADB002`. Đây là "header multiboot" trong `boot.asm`.
2. Nó nạp kernel vào RAM ở địa chỉ `linker.ld` yêu cầu (1 MB), rồi bật protected mode.
3. Nó đặt `EAX = 0x2BADB002` (báo "tôi là bootloader multiboot") và `EBX` = địa chỉ bảng thông tin (bộ nhớ, dòng lệnh...).
4. Nó nhảy tới `_start`.

Hôm nay bạn làm phần việc của BIOS và boot sector bằng tay, để thấy tận mắt bước số 3 trong chuỗi khởi động.

## Code

Tạo thư mục thí nghiệm riêng để không đụng vào kernel đang có:

```bash
mkdir -p ~/myos/experiments/bootsector
cd ~/myos/experiments/bootsector
```

Tạo file `bootsect.asm` với nội dung sau:

```nasm title=bootsect.asm
; bootsect.asm - a 512-byte boot sector: the BIOS loads it to 0x7C00 and jumps to it
bits 16                     ; the CPU starts in 16-bit real mode
org 0x7C00                  ; tell NASM our code will live at address 0x7C00

start:
    cli                     ; no interrupts while we set up segments and stack
    xor ax, ax              ; ax = 0
    mov ds, ax              ; data segment = 0
    mov es, ax              ; extra segment = 0
    mov ss, ax              ; stack segment = 0
    mov sp, 0x7C00          ; stack grows down, just below our code
    sti                     ; interrupts back on (the BIOS needs them)
    cld                     ; lodsb walks forward through memory

    mov si, message         ; si = address of the first character
.next_char:
    lodsb                   ; al = byte at [si], then si = si + 1
    test al, al             ; is it the 0 that ends the string?
    jz .done
    mov ah, 0x0E            ; BIOS function 0x0E: print one character
    mov bh, 0               ; video page 0
    int 0x10                ; call the BIOS video service
    jmp .next_char

.done:
    cli                     ; nothing left to do: stop interrupts
.hang:
    hlt                     ; sleep the CPU
    jmp .hang               ; if something wakes it, sleep again

message:
    db "Hello from the boot sector!", 13, 10
    db "The BIOS loaded me at 0x7C00.", 13, 10, 0

times 510 - ($ - $$) db 0   ; fill with zeros up to byte 510
dw 0xAA55                   ; boot signature, stored as 55 AA
```

### Lệnh build và chạy

```bash
nasm -f bin bootsect.asm -o bootsect.bin
ls -l bootsect.bin
xxd bootsect.bin | tail -n 1
qemu-system-i386 -drive format=raw,file=bootsect.bin
```

Nếu QEMU không mở được cửa sổ trên WSL, chạy trong terminal bằng:

```bash
qemu-system-i386 -drive format=raw,file=bootsect.bin -display curses
```

Thoát chế độ `curses`: nhấn **Esc** rồi phím **2** để vào màn hình điều khiển của QEMU, gõ `quit` rồi Enter.

## Giải thích từng dòng

| Dòng code | Giải thích |
|---|---|
| `bits 16` | Báo NASM sinh mã máy 16 bit. Vì sao: lúc BIOS chạy boot sector, CPU đang ở real mode 16 bit, mã 32 bit sẽ bị hiểu sai. |
| `org 0x7C00` | Báo NASM "code này sẽ nằm ở địa chỉ 0x7C00". Vì sao: để NASM tính đúng địa chỉ của nhãn `message`. Thiếu dòng này, `mov si, message` sẽ trỏ sai chỗ và in ra rác. |
| `cli` | Tắt ngắt. Thay đổi cờ IF trong thanh ghi FLAGS về 0. Vì sao: lúc đang đổi `ss` và `sp`, nếu ngắt xảy ra thì CPU dùng stack nửa cũ nửa mới và hỏng. |
| `xor ax, ax` | Đặt `ax` = 0 (một số XOR chính nó luôn bằng 0). Vì sao: ngắn hơn `mov ax, 0`, và thanh ghi segment không nhận giá trị trực tiếp nên phải đi qua `ax`. |
| `mov ds, ax` / `mov es, ax` / `mov ss, ax` | Đặt ba thanh ghi segment `ds`, `es`, `ss` về 0. Vì sao: real mode tính địa chỉ bằng segment × 16 + offset. Có BIOS để lại `ds` khác 0, nên phải tự đặt cho chắc. |
| `mov sp, 0x7C00` | Thanh ghi `sp` (đỉnh stack) = 0x7C00. Vì sao: stack mọc **xuống** địa chỉ thấp hơn, nên nó dùng vùng trống ngay dưới code mà không đè lên code. |
| `sti` | Bật lại ngắt (IF = 1). Vì sao: dịch vụ `int 0x10` của BIOS có thể cần ngắt để chạy. |
| `cld` | Xoá cờ hướng DF. Vì sao: để `lodsb` **tăng** `si` sau mỗi lần đọc. Nếu DF = 1 thì nó đi lùi. |
| `mov si, message` | `si` = địa chỉ chữ cái đầu của chuỗi. Vì sao: `lodsb` luôn đọc từ địa chỉ trong `si`. |
| `lodsb` | Đọc 1 byte tại `[si]` vào `al`, rồi `si` tăng 1. Vì sao: lấy từng chữ một, giống `for ch in message` trong Python. |
| `test al, al` / `jz .done` | Kiểm tra `al` có bằng 0 không (đặt cờ ZF), nếu bằng thì nhảy tới `.done`. Vì sao: chuỗi kết thúc bằng byte 0, giống chuỗi trong C. |
| `mov ah, 0x0E` | `ah` = 0x0E, mã chức năng "in một ký tự" của BIOS. Vì sao: `int 0x10` có nhiều chức năng, chọn chức năng bằng `ah`. |
| `mov bh, 0` | `bh` = 0, chọn trang màn hình số 0. |
| `int 0x10` | Gọi dịch vụ màn hình của BIOS, in ký tự trong `al` và tự dịch con trỏ. Vì sao: trong real mode đây là cách in chữ dễ nhất. Kernel protected mode không dùng được cách này. |
| `jmp .next_char` | Quay lại đọc chữ tiếp theo. |
| `cli` / `hlt` / `jmp .hang` | Tắt ngắt rồi cho CPU ngủ. Vòng `jmp` phòng khi có ngắt không chặn được (NMI) đánh thức CPU. Vì sao: nếu không dừng, CPU chạy tiếp vào vùng `message` và coi chữ là lệnh, gây treo hoặc khởi động lại. |
| `db "Hello...", 13, 10` | Ghi các byte của chuỗi vào file. 13 là về đầu dòng (CR), 10 là xuống dòng (LF). Vì sao: BIOS cần cả hai mới xuống dòng đúng. |
| `db "...", 13, 10, 0` | Dòng thứ hai, kết thúc bằng byte 0 để vòng lặp biết chỗ dừng. |
| `times 510 - ($ - $$) db 0` | Thêm byte 0 cho đủ 510 byte. `$` là vị trí hiện tại, `$$` là đầu file, nên `$ - $$` là số byte đã viết. Vì sao: chữ ký phải nằm đúng byte 510 và 511. |
| `dw 0xAA55` | Ghi 2 byte chữ ký khởi động. x86 lưu số theo kiểu **little-endian** (byte thấp trước), nên trong file là `55 AA`. Vì sao: BIOS chỉ chạy sector có chữ ký này. |

## Kết quả mong đợi

`ls -l` báo file đúng **512** byte. Dòng cuối của `xxd` kết thúc bằng `55aa`:

```text
000001f0: 0000 0000 0000 0000 0000 0000 0000 55aa  ..............U.
```

Cửa sổ QEMU hiện:

```text
SeaBIOS (version ...)
...
Booting from Hard Disk...
Hello from the boot sector!
The BIOS loaded me at 0x7C00.
_
```

Con trỏ nhấp nháy đứng yên ở dòng dưới: CPU đang "ngủ" ở vòng `.hang`. Đóng cửa sổ QEMU để thoát.

## Lỗi hay gặp

### QEMU báo "Boot failed: not a bootable disk"

Sau đó QEMU thử Floppy, CD, rồi khởi động qua mạng (iPXE). Nguyên nhân: 2 byte cuối không phải `55 AA`, thường do quên dòng `dw 0xAA55` hoặc gõ sai thành `0x55AA`. Kiểm tra bằng `xxd bootsect.bin | tail -n 1`.

### NASM báo "TIMES value -90 is negative"

Code và dữ liệu đã dài quá 510 byte, nên `510 - ($ - $$)` ra số âm. Con số trong thông báo cho biết bạn thừa bao nhiêu byte. Hãy rút ngắn chuỗi chữ. Đây là giới hạn thật của boot sector, và là lý do bootloader thật như GRUB phải chia làm nhiều giai đoạn.

### Màn hình in ra ký tự rác hoặc không in gì

Thường do thiếu `org 0x7C00`, nên `message` trỏ sai địa chỉ, hoặc quên byte `0` cuối chuỗi khiến vòng lặp in tràn qua cả vùng nhớ phía sau. Nếu QEMU không mở cửa sổ trên WSL, hãy dùng `-display curses`.

## Bài tập

### Dễ

Đổi lời chào thành tên của bạn và thêm một dòng thứ ba ghi ngày hôm nay. Build lại và kiểm tra file vẫn đúng 512 byte.

Gợi ý: Chỉ cần sửa và thêm các dòng `db`. Nhớ chỉ dòng **cuối cùng** mới có byte `0`, các dòng trước kết thúc bằng `13, 10`.

### Vừa

Tách phần in chuỗi thành một "hàm" tên `print_string`: nhận địa chỉ chuỗi trong `si`, in ra, rồi quay về. Dùng nó để in **hai** chuỗi khác nhau ở hai chỗ khác nhau trong chương trình.

Gợi ý: Trong assembly, gọi hàm bằng `call print_string`, và hàm kết thúc bằng `ret`. `call` cất địa chỉ quay về lên stack. Đó là lý do bạn phải đặt `sp` trước khi dùng.

### Khó

Biến boot sector thành máy "gõ gì hiện nấy": chờ người dùng gõ phím, in lại đúng ký tự đó, và khi gõ Enter thì xuống dòng.

Gợi ý: BIOS có dịch vụ bàn phím `int 0x16` với `ah = 0`: nó chờ đến khi có phím, rồi trả mã ASCII trong `al`. Phím Enter cho mã 13. Để xuống dòng, hãy in thêm ký tự 10.

## Bản nghe

Bài không chấm một. Máy tính khởi động thế nào.

Khi bạn bấm nút nguồn, CPU chưa biết gì cả. Nó chỉ biết nhảy tới một địa chỉ cố định trong chip ROM, nơi có firmware tên là BIOS. BIOS kiểm tra phần cứng, rồi đọc sector đầu tiên của ổ đĩa. Sector này dài đúng năm trăm mười hai byte.

Hai byte cuối của sector phải là năm mươi lăm và A A. Đó là chữ ký khởi động. Nếu đúng, BIOS chép sector vào bộ nhớ tại địa chỉ không x bảy C không không, rồi nhảy tới đó. Nếu sai, BIOS báo đĩa không khởi động được.

Lúc này CPU đang ở real mode, chế độ mười sáu bit, chỉ dùng được khoảng một mê ga byte bộ nhớ. Bù lại, ta được gọi dịch vụ của BIOS, ví dụ lệnh int không x mười để in chữ.

Trong bài, bạn viết một boot sector nhỏ. Nó đặt các thanh ghi segment về không, đặt stack ngay dưới code, rồi đọc từng chữ của chuỗi và nhờ BIOS in ra. Gặp byte không thì dừng, cho CPU ngủ mãi.

Kernel bạn đã viết thì khác. Bootloader theo chuẩn multiboot đã chuyển CPU sang protected mode ba mươi hai bit và nạp kernel vào địa chỉ một mê ga byte. Vì vậy kernel không gọi được BIOS nữa, mà phải tự ghi chữ vào bộ nhớ màn hình.

Nhớ ba ý: không x bảy C không không, chữ ký năm mươi lăm A A, và real mode khác protected mode.
