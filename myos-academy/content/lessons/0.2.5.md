# Bài 0.2.5: Assembly 5: C++ gọi assembly (cdecl)

## Mục tiêu

Hiểu **quy ước gọi hàm cdecl**, để C++ gọi được hàm viết bằng assembly và ngược lại. Cuối bài bạn viết hàm `add_numbers` bằng assembly, gọi nó từ C++, và hiểu từng dòng của đoạn `boot.asm` gọi `kernel_main`. Đây là **bài tập lớn của Giai đoạn 0**.

## Lý thuyết

### Vì sao cần quy ước

Ở bài trước, hàm `double_it` nhận đầu vào trong `eax`. Đó là luật do chính bạn đặt ra. Nhưng trình biên dịch C++ không biết luật đó. Muốn hai bên nói chuyện được, phải theo một "hợp đồng" chung. Trên Linux 32 bit, hợp đồng đó tên là **cdecl**:

1. Người gọi **đẩy tham số lên stack từ phải sang trái**: tham số cuối được đẩy trước.
2. `call` đẩy địa chỉ quay về, rồi nhảy vào hàm.
3. Giá trị trả về nằm trong **`eax`**.
4. Hàm được gọi phải giữ nguyên `ebx`, `esi`, `edi`, `ebp`. Còn `eax`, `ecx`, `edx` thì được phép làm hỏng.
5. Người gọi tự **dọn tham số** khỏi stack sau khi hàm trả về, bằng `add esp, ...`.

### Khung stack và ebp

`esp` thay đổi mỗi khi `push` hay `pop`, nên khó dùng làm mốc để tìm tham số. Vì vậy đầu mỗi hàm thường có hai dòng quen thuộc:

```nasm
push ebp        ; keep the caller's ebp
mov ebp, esp    ; ebp = a fixed point for this function
```

Từ đó tham số luôn nằm ở vị trí cố định so với `ebp`:

![Khung stack khi gọi add_numbers(30, 12)](images/asm-call-frame.png)

Tham số đầu tiên ở `[ebp + 8]` vì giữa nó và `ebp` còn **ebp cũ** (4 byte) và **địa chỉ quay về** (4 byte).

### extern "C" và name mangling

C++ cho phép nhiều hàm trùng tên khác tham số, nên trình biên dịch **đổi tên** hàm trong file `.o`. Ví dụ `add_numbers(int, int)` thành `_Z11add_numbersii`. Gọi là **name mangling**. Viết `extern "C"` để giữ tên gốc `add_numbers`, khớp với nhãn trong file assembly.

### Nhìn lại kernel của bạn

Giờ bạn đọc được đoạn quen thuộc trong `boot.asm`:

```nasm
mov esp, stack_top   ; prepare a stack: call and push need one
push ebx             ; second argument of kernel_main: multiboot info address
push eax             ; first argument: the multiboot magic number
call kernel_main     ; C++ takes over from here
```

Tham số đẩy **từ phải sang trái**, rồi `call`. Đó đúng là cdecl. Còn `kernel_main` được khai báo `extern "C"` trong `kernel.cpp` để tên khớp.

### Hoạt hình

Bấm **🎬 Xem hoạt hình** để xem toàn bộ quá trình: người gọi đẩy 12 rồi 30, `call` thêm địa chỉ quay về, hàm dựng khung với `ebp`, đọc `[ebp + 8]` và `[ebp + 12]`, rồi trả 42 trong `eax`.

## Code

Chương trình không dùng thư viện C (giống kernel), nên tự viết điểm bắt đầu `_start` trong `start.asm`.

```nasm title=add.asm
; add.asm - int add_numbers(int a, int b) using the cdecl calling convention
bits 32

section .text
global add_numbers
add_numbers:
    push ebp                ; save the caller's frame pointer
    mov ebp, esp            ; ebp = start of our stack frame
    mov eax, [ebp + 8]      ; eax = a (first argument)
    add eax, [ebp + 12]     ; eax = a + b (second argument)
    pop ebp                 ; restore the caller's frame pointer
    ret                     ; return to the caller; the result is in eax
```

```nasm title=start.asm
; start.asm - program entry without the C library: call main, exit with its return value
bits 32

section .text
global _start
extern main
_start:
    call main               ; eax = main()
    mov ebx, eax            ; exit code = return value of main
    mov eax, 1              ; syscall number 1 = exit
    int 0x80
```

```cpp title=main.cpp
// main.cpp - calls a function written in assembly; no standard library (same rules as the kernel)
extern "C" int add_numbers(int a, int b);

extern "C" int main() {
    int result = add_numbers(30, 12);
    return result;  // becomes the exit code: `echo $?` prints 42
}
```

Build và chạy:

```bash
nasm -f elf32 add.asm -o add.o
nasm -f elf32 start.asm -o start.o
g++ -m32 -ffreestanding -fno-exceptions -fno-rtti -fno-pie -fno-stack-protector -O0 -c main.cpp -o main.o
ld -m elf_i386 -z noexecstack start.o main.o add.o -o add_demo
./add_demo
echo $?
```

Các cờ của `g++` giống hệt lúc build kernel. Cờ `-z noexecstack` chỉ để tắt một cảnh báo vô hại của `ld`.

Xem trình biên dịch gọi hàm thế nào:

```bash
objdump -d -M intel main.o
```

Trong phần `<main>`, tìm ba dòng `push 0xc`, `push 0x1e`, `call`. `0xc` là 12, `0x1e` là 30: đẩy 12 trước, 30 sau, đúng thứ tự từ phải sang trái. Những dòng còn lại là phần trình biên dịch thêm để căn chỉnh stack, chưa cần hiểu.

## Giải thích từng dòng

| Dòng code | Giải thích |
|---|---|
| `global add_numbers` | Cho file khác thấy hàm. Thiếu dòng này, `ld` báo `undefined reference`. |
| `push ebp` | Cất `ebp` của người gọi. `esp` giảm 4. Vì sao: cdecl bắt phải trả lại `ebp` nguyên vẹn. |
| `mov ebp, esp` | `ebp` thành mốc cố định của hàm. |
| `mov eax, [ebp + 8]` | Đọc tham số `a` = 30. |
| `add eax, [ebp + 12]` | Cộng tham số `b` = 12. `eax` = 42. |
| `pop ebp` | Trả lại `ebp` cũ. `esp` trỏ đúng vào địa chỉ quay về. |
| `ret` | Quay về người gọi. Kết quả đã nằm sẵn trong `eax`, đúng chỗ C++ chờ đọc. |
| `extern main` | Báo NASM: `main` nằm ở file khác. |
| `call main` / `mov ebx, eax` | Chạy `main` của C++, lấy giá trị trả về làm mã thoát. |
| `extern "C" int add_numbers(int a, int b);` | Khai báo hàm viết ở file khác, giữ tên gốc để khớp với nhãn assembly. |
| `extern "C" int main()` | Giữ tên `main` để `start.asm` gọi được. |
| `int result = add_numbers(30, 12);` | Trình biên dịch sinh `push 12`, `push 30`, `call add_numbers`, dọn stack, rồi đọc `eax`. |

```text
$ ./add_demo

42
```

`objdump` cho thấy `push 0xc` rồi `push 0x1e` ngay trước `call` trong `<main>`.

## Lỗi hay gặp

### `undefined reference to add_numbers`

Thiếu `global add_numbers` trong `add.asm`, hoặc thiếu `extern "C"` trong `main.cpp`. Dùng `nm main.o` để xem tên thật mà C++ đang tìm: nếu thấy `_Z11add_numbersii` thì là do thiếu `extern "C"`.

### Kết quả sai dù không lỗi

Đọc nhầm vị trí tham số, ví dụ `[ebp + 4]`: đó là địa chỉ quay về chứ không phải tham số. Hoặc quên `mov ebp, esp`, khiến `ebp` vẫn là của người gọi.

### `Segmentation fault`

Quên `pop ebp` trước `ret`, nên `ret` lấy `ebp` cũ làm địa chỉ quay về. Mỗi `push` phải có một `pop`.

## Bài tập

### Dễ

Đổi lời gọi thành `add_numbers(100, 23)`, build lại và kiểm tra. Đáp án đúng là 123. Chạy lại `objdump` và tìm hai con số mới ở dạng hex.

Gợi ý: 100 là `0x64`, 23 là `0x17`. Đẩy số nào trước?

### Vừa

Viết hàm assembly `int max_of(int a, int b)` trả về số lớn hơn, và gọi nó từ C++. Thử `max_of(7, 19)` và `max_of(25, 3)`.

Gợi ý: Đọc `a` vào `eax`, `cmp eax, [ebp + 12]`. Nếu lớn hơn hoặc bằng thì nhảy (`jge`) tới cuối hàm. Nếu không thì chép `b` vào `eax`. Cuối hàm vẫn là `pop ebp` rồi `ret`.

### Khó

Viết hàm assembly `int factorial(int n)` tính n giai thừa bằng vòng lặp, gọi từ C++ với n = 5. Đáp án đúng là 120.

Gợi ý: `eax` bắt đầu bằng 1, `ecx` = n đọc từ `[ebp + 8]`. Mỗi vòng `imul eax, ecx` rồi `dec ecx`, và `jnz` để lặp tiếp. `ecx` được phép làm hỏng theo cdecl, nên không cần cất nó.

## Bản nghe

Bài không chấm hai chấm năm. C cộng cộng gọi assembly theo quy ước c decl.

Muốn C cộng cộng và assembly gọi được nhau, hai bên phải theo cùng một hợp đồng. Trên Linux ba mươi hai bit, hợp đồng đó là c decl.

Thứ nhất, người gọi đẩy tham số lên stack từ phải sang trái. Thứ hai, lệnh call đẩy thêm địa chỉ quay về. Thứ ba, giá trị trả về nằm trong e a x. Thứ tư, hàm phải giữ nguyên e b x, e s i, e d i và e b p. Cuối cùng, người gọi tự dọn tham số khỏi stack.

Đầu mỗi hàm thường có hai lệnh: push e b p, rồi mov e b p, e s p. Từ đó e b p là mốc cố định. Tham số đầu tiên nằm ở e b p cộng tám, tham số thứ hai ở e b p cộng mười hai. Giữa chúng và e b p là e b p cũ và địa chỉ quay về.

C cộng cộng tự đổi tên hàm trong file object, gọi là name mangling. Viết extern C để giữ đúng tên, khớp với nhãn trong file assembly.

Giờ bạn đọc được boot chấm a s m. Push e b x, push e a x, rồi call kernel main. Đó chính là c decl.
